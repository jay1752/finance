# Database Setup Guide

This document explains how to set up and use the database for the Indian Stock Market Analysis platform.

## 📊 Overview

The platform supports **two database types**:

1. **SQLite** (Default) - File-based, perfect for development and single-user
2. **PostgreSQL** - Production-grade, recommended for multi-user and scalability

---

## 🚀 Quick Start (SQLite)

SQLite is **already configured** and ready to use!

### 1. Initialize Database

```bash
# Create tables and seed sample stocks
python scripts/init_database.py --seed

# Verify setup
python scripts/init_database.py --verify
```

### 2. Database Location

```
data/stock_analysis.db
```

### 3. Start Using

The database is automatically used by all components. No additional configuration needed!

## 🗄️ Production Setup (PostgreSQL)

For production deployments with multiple users or large datasets.

### 1. Install PostgreSQL

**macOS:**
```bash
brew install postgresql@15
brew services start postgresql@15
```

**Ubuntu/Debian:**
```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
```

**Windows:**
Download from: https://www.postgresql.org/download/windows/

### 2. Create Database

```bash
# Connect to PostgreSQL
psql -U postgres

# Create database and user
CREATE DATABASE stock_analysis;
CREATE USER stock_user WITH PASSWORD 'your_secure_password';
GRANT ALL PRIVILEGES ON DATABASE stock_analysis TO stock_user;

# Exit
\q
```

### 3. Configure Environment

Create a `.env` file in the project root:

```env
# Database Configuration
DB_TYPE=postgresql
DB_HOST=localhost
DB_PORT=5432
DB_NAME=stock_analysis
DB_USER=stock_user
DB_PASSWORD=your_secure_password
```

### 4. Initialize Database

```bash
# Load environment variables
source .env  # or use `export $(cat .env | xargs)` on some systems

# Initialize
python scripts/init_database.py --seed
```

### 5. Optional: TimescaleDB (for time-series optimization)

```bash
# macOS
brew install timescaledb

# Ubuntu
sudo add-apt-repository ppa:timescale/timescaledb-ppa
sudo apt install timescaledb-2-postgresql-15

# Enable extension
psql -U stock_user -d stock_analysis
CREATE EXTENSION IF NOT EXISTS timescaledb;
```

## 📊 Database Schema

### Tables

| Table | Description |
|-------|-------------|
| **stocks** | Master list of stocks (symbol, name, sector, etc.) |
| **stock_prices** | Historical OHLCV price data |
| **signals** | Trading signals generated by strategies |
| **backtest_results** | Backtest performance metrics |
| **fii_dii_data** | FII/DII institutional flows (India-specific) |
| **delivery_data** | Delivery percentage data (India-specific) |

### Entity Relationships

```
stocks (1) ----< (N) stock_prices
stocks (1) ----< (N) signals
stocks (1) ----< (N) backtest_results
stocks (1) ----< (N) delivery_data
```

## 🔧 Database Operations

### Using in Code

```python
from src.database import get_db, Stock, Signal

# Get database instance
db = get_db()

# Query stocks
with db.get_session() as session:
    stocks = session.query(Stock).filter_by(exchange='NSE').all()

    for stock in stocks:
        print(f"{stock.symbol}: {stock.name}")

# Add a signal
with db.get_session() as session:
    reliance = session.query(Stock).filter_by(symbol='RELIANCE').first()

    signal = Signal(
        stock_id=reliance.id,
        strategy_name='RSI',
        signal_type='BUY',
        signal_date=datetime.now(),
        price=2847.50,
        confidence=75.0,
        signal_metadata={'rsi': 28.5}
    )

    session.add(signal)
    # Auto-commits on context manager exit
```

### Command-Line Tools

```bash
# Initialize/recreate database
python scripts/init_database.py --seed

# Verify database
python scripts/init_database.py --verify

# Reset database (WARNING: deletes all data!)
python scripts/init_database.py --reset --seed
```

## 🔄 Switching Between SQLite and PostgreSQL

### Switch to PostgreSQL

```bash
# Set environment variables
export DB_TYPE=postgresql
export DB_HOST=localhost
export DB_PORT=5432
export DB_NAME=stock_analysis
export DB_USER=stock_user
export DB_PASSWORD=your_password

# Reinitialize
python scripts/init_database.py --seed
```

### Switch back to SQLite

```bash
# Unset environment variables
unset DB_TYPE

# Or restart your terminal
# SQLite will be used automatically
```

## 📈 Performance Tips

### SQLite
- ✅ Perfect for development and single-user
- ✅ No installation required
- ✅ File-based (easy backup: just copy the .db file)
- ⚠️ Limited concurrency (one writer at a time)
- ⚠️ Not ideal for > 100K records per table

### PostgreSQL
- ✅ Production-ready
- ✅ Excellent concurrency (multiple writers)
- ✅ Advanced features (JSON, full-text search, time-series)
- ✅ Scalable to millions of records
- ⚠️ Requires installation and configuration
- ⚠️ More complex backup/restore

## 🔍 Troubleshooting

### "No module named 'psycopg2'"

PostgreSQL connector not installed:

```bash
pip install psycopg2-binary
```

### "Could not connect to database"

Check PostgreSQL is running:

```bash
# macOS
brew services list | grep postgresql

# Ubuntu
sudo systemctl status postgresql
```

### "Permission denied"

Grant permissions:

```sql
GRANT ALL PRIVILEGES ON DATABASE stock_analysis TO stock_user;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO stock_user;
```

### Database is locked (SQLite)

Only one write operation at a time. Close other connections or use PostgreSQL.

## 📦 Backup and Restore

### SQLite

**Backup:**
```bash
cp data/stock_analysis.db data/stock_analysis_backup_$(date +%Y%m%d).db
```

**Restore:**
```bash
cp data/stock_analysis_backup_20250109.db data/stock_analysis.db
```

### PostgreSQL

**Backup:**
```bash
pg_dump -U stock_user -d stock_analysis -f backup_$(date +%Y%m%d).sql
```

**Restore:**
```bash
psql -U stock_user -d stock_analysis -f backup_20250109.sql
```

## 🎯 Best Practices

1. **Development**: Use SQLite for quick iterations
2. **Production**: Use PostgreSQL for reliability
3. **Backups**: Regular automated backups (daily for production)
4. **Indexes**: Already optimized in schema
5. **Migrations**: Use `init_database.py --reset` carefully (deletes data!)
6. **Security**: Never commit `.env` file with passwords
